# Risks — Questify

> What could go wrong, and the plan. Drafted in Stage 8, 2026-10-17. Likelihood and impact are
> Claude's estimates unless marked as the user's decision. Owner is Dhia unless named.

| # | Risk | Likelihood | Impact | Mitigation | Owner |
|---|---|---|---|---|---|
| R1 | **Scope against capacity.** About 516 requirements, everything in v1, one developer plus Claude, no review point or cut order (ADR-069, Q-077). The first event can slip without limit | High | High | Build thin slices first (Phase 1) and keep Musts first. Claude's suggestions, not decided (the user declined a review point and a cut order): review progress at phase boundaries and agree a cut line before an event date is promised | Dhia |
| R2 | **Players will not install an app** to play an event (the riskiest business assumption) | Medium | High | One-scan join, browse before sign-in, a web event page, the 3-minute first-coin target (ADR-098); measure activation at the first three events and stop adding features if under 20% twice | Dhia |
| R3 | **SMS gateway outage or SMS pumping** at an event start. One gateway chosen, no automatic second one (grill 3) | Medium | High | Email-code fallback after 30 s; per-number and global limits; cost alert in the usage view; written quotes from both Msegat and Taqnyat so the second can be switched on by a person; suggestion to invite players to add an email after first sign-in | Dhia |
| R4 | **CranL does not meet the recovery targets as documented** (ADR-107 addendum): snapshots are public-schema rows only, kept 7 days, no point-in-time recovery. High availability, uptime and hosting provider are still unpublished. Managed PostgreSQL may not be offered in the chosen region; AWS and Azure Saudi are not live | Medium | High | Ask CranL the written question list; keep a second nightly backup copy in another Saudi place; pass the restore rehearsal (T-805); move to Oracle, sccc or Google Dammam if they fall short | Dhia |
| R5 | **Load target missed** (20,000 completions per minute per event, ten events) | Low to medium | High | Launch gate: load test (T-804); scale the database up and add replicas first; burst queue only if proven needed (grill 1) | Dhia |
| R6 | **Cross-tenant data leak** or a public-credential hole (for example privileged database functions left callable by anyone) | Low | Very high | Row-level security, deny-by-default, outsider and cross-tenant suites in every CI run; Max bar on the core (ADR-104) | Dhia |
| R7 | **Store review rejection** (Apple 2.5.2, 4.2, user-generated content, wallet logo, EU storefront rules) | Medium | High | `STORE_COMPLIANCE.md` is a gate; review demo tenant; no downloaded features; ask counsel on wallet data abroad; Q-076 unverified assumption that Apple allows an organizer logo on a Questify-signed pass | Dhia |
| R8 | **Legal gaps** (PDPL, retention periods, data controller named when the store seller is the individual, Q-075, Q-078, Q-051, wallet data abroad) | Medium | High | One batched Saudi lawyer review (T-807) before launch; items the user states as "yes" are marked unverified until counsel confirms | Dhia |
| R9 | **Admin account takeover** (email, password and a code; one admin role; many powers, ADR-078, ADR-094) | Low | Very high | Short sessions, session list and forced sign-out, every admin action logged, alert on new admin sign-in; the user considers this "very safe" and the residual risk is accepted | Dhia |
| R10 | **A bad live configuration save** reaches every player at once (no draft, rollback or A/B, ADR-093) | Medium | Medium | Validation on save, protected items and placeholders, audit log, the phone's last-working copy (F-282); revisit draft/publish after launch | Dhia |
| R11 | **Arabic and RTL quality** (React Native restarts on language switch; Arabic text bugs on real devices) | Medium | Medium | Test on real phones from Phase 0; Q-079 decides the switch behaviour; final Arabic copy pass (T-808) | Dhia |
| R12 | **iPhone one-scan join is imperfect** (Q-070): the iPhone path needs one tap | Medium | Medium | Paste-code button plus typing the short code; Android uses the install referrer; measure install-to-first-coin | Dhia |
| R13 | **NFC tags can be cloned** (Q-071) | Medium | Medium | Signed per-tap tags if the library supports configuring them, otherwise flags and QR as the main proof | Dhia |
| R14 | **Dependency churn** in Expo and React Native (several SDK releases a year) | Medium | Low to medium | Pin versions, upgrade between phases, keep the dependency list short (rules.md) | Dhia |
| R15 | **Cloud-build queue or outage** on the free Expo plan before a release | Low | Medium | Upgrade to the $19 plan near a release; a borrowed Mac with Xcode is the fallback | Dhia |
| R16 | **Mascot and art assets delayed** (Codex image limit, resets 18 Oct; seven mascot images remain; mascot vote Q-069) | Medium | Low | Theme-agnostic UX plan; screens work with placeholder art; design tokens allow later swaps | Dhia |
| R17 | **Unit economics unknown** (SMS cost absorbed by Questify; per-event prices outside the platform; no prices yet) | Medium | Medium | Usage view; written SMS quotes; set price tiers before the first paid event | Dhia |
| R18 | **A key person risk:** one developer; no second reader for core changes | Medium | High | Max-bar second read via review agents; documentation kept alive; keep the build runnable from a fresh checkout | Dhia |
