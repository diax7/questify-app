# Plan: T-004 Audit log

> Quality bar: Max (admin powers, accountability). Delivers FR-1029 (event change log), FR-1030 (entries can never be
> edited or deleted), FR-1410 (every console action logged), NFR-019. Done when: any update or delete of an audit row
> fails at the database; each state-changing call writes who, what, before, after and when.

## Scope
**In:** the `audit_log` table (append-only at the database), one helper that writes an entry inside the caller's own
transaction, a key deny-list so secrets never land in it, and wiring into every state-changing call that exists today:
platform settings, event feature switches, add-on unlock and lock, translations, staff session opened and ended, and
the two staff CLI commands.
**Out (with a home):** the change-log screens and their read routes (T-604 dashboard, T-701 console); anonymising a
deleted player's entries (with account deletion, T-1xx; the trigger keeps a single sanctioned path for it, see below);
moving failed sign-in attempts here (they stay log lines: no identity, high volume, abuse traffic).

## Design
### Table (migration 0006)
`audit_log(id bigint identity PK, at timestamptz default now(), actor_type text CHECK in (admin, staff, player, system),
actor_id uuid NULL, organizer_id uuid NULL, event_id uuid NULL, action text CHECK dotted lower-case, target_type text,
target_id text, before jsonb NULL, after jsonb NULL, request_id text NULL)`, indexes on `(organizer_id, at DESC)`,
`(event_id, at DESC)`, `(actor_id, at DESC)`.
- No client address: the request id ties an entry to the server log line, which holds a keyed address tag only.
- `event_id` must belong to `organizer_id` when both are set (composite FK to `event (id, organizer_id)`).

### Append-only (FR-1030)
- Grants: the API role gets `SELECT, INSERT` only (no UPDATE, DELETE, TRUNCATE).
- A `BEFORE UPDATE OR DELETE` row trigger and a `BEFORE TRUNCATE` statement trigger raise for **every** role, the owner
  included. The only exception is a future anonymisation function (not built now) that will set a transaction-local
  flag the trigger checks; until it exists, nothing can change a row.
- Tests from the API role's seat and from the owner connection: update, delete and truncate all fail.

### Who may write and read (RLS)
- Insert: the actor must be the caller. `admin` needs `app_is_admin()` and `actor_id = app_staff_user_id()`; `staff`
  needs `actor_id = app_staff_user_id()` and, when `organizer_id` is set, `organizer_id = app_organizer_id()`;
  `player` needs `actor_id = app_player_id()`; `system` (CLI, jobs) is written by the owner connection only (the API
  role may not claim it). So nobody can write an entry in someone else's name.
- Read: an organizer reads entries with its `organizer_id` (this includes a Questify admin's support access to its
  events, ADR-068); a Questify admin reads everything; nobody else.

### Helper (`apps/api/src/audit/`)
`recordAudit(client, entry)`: inserts one row in the transaction the caller already opened, so a change and its entry
commit or roll back together. `diff(before, after)` keeps only the top-level keys that changed. A deny-list refuses
keys that look like secrets (`password`, `passwordHash`, `token`, `tokenHash`, `code`, `codeHash`, `secret`) at any
depth: a refused entry throws, which rolls back the change, so a bug cannot quietly leak a secret into a permanent
record. Action names are dotted lower-case words (`platform_settings.update`).

### Wiring (each in the same transaction as the change)
| Call | Action | Actor | Before / after |
|---|---|---|---|
| savePlatformSettings | `platform_settings.update` | admin | the blocks that changed |
| saveEventSwitches | `event.features.update` | staff (organizer, event) | the feature switches |
| unlockFeature / lockFeature | `event.addon.unlock` / `.lock` | admin (organizer, event) | the feature name |
| translation save | `translation.update` | admin | the languages that changed |
| code step → session opened | `staff.session.open` | staff | session id (no token, no address) |
| sign-out, end a session | `staff.session.end` | staff | session id |
| CLI create, clear-throttle | `staff.create`, `staff.throttle.clear` | system | user id and role; no email |

`saveEventSwitches` today takes an organizer id but no staff user id; it gains the actor (needed for "who").

## Tests
Integration (real PostgreSQL): append-only from both seats; insert impersonation refused for each actor type; an
organizer reads only its own entries and sees an admin's support entries for its events; another organizer sees none;
the outsider can do nothing; each wired call writes exactly one entry with the right before and after and nothing when
the change is refused; a change and its entry roll back together; a secret key refused at any depth.
Unit: `diff`, the deny-list, the action format. Mutation: the audit module joins the core scope (target 90%).

## Judgment calls
1. No client address in the table (the request id is the link); revisit if counsel wants it (Q-075).
2. Failed sign-ins stay in the server log, not here.
3. The trigger blocks even the owner connection, so a mistake in a migration cannot rewrite history; a future
   anonymisation path will be the one sanctioned exception.

## As built (after the CTO plan review, 84/100, no blockers)
- `id` is `GENERATED ALWAYS`; the API's INSERT grant names the columns, so it can set neither `id` nor `at`.
- No foreign keys; deleting an event keeps its entries (tested).
- The insert policy has no `system` branch: system entries come only from the owner connection (CLI, jobs).
  An entry about an event must name that event's organizer (checked against `event`), and the table also checks
  `event_id IS NULL OR organizer_id IS NOT NULL`.
- Both triggers are `ENABLE ALWAYS` and a test asserts `tgenabled = 'A'`.
- The deny-list normalises keys (lower case, no `_` or `-`) and refuses endings `password`, `passwordhash`,
  `secret`, `token`, `tokenhash`, `codehash`, `apikey` and exact keys `code`, `email`, `phone`, `phonee164`, `ip`,
  `useragent`, `cookie`, `authorization`.
- Each wired call locks the current value (`FOR UPDATE`), diffs it, and writes nothing when nothing changed.
- `saveEventSwitches` takes `{ staffUserId, organizerId }`; services take an optional `{ requestId }`.
- `revokeAllSessions` was removed as dead code; it returns with T-020 and must write `staff.session.end_all`.
- Failed sign-ins stay in the server log (TASKS T-004 note). Retention and anonymisation: Q-084.
- Mutation: `apps/api/src/audit/**` joined the core scope.
