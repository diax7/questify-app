## Design

1. **`legal_version`** (append-only for every role, closed table), seeded 0.1 for the six documents. In force = latest by three
   numbers. `legal_in_force()`, `legal_text()` public reads; `admin_legal_list()`, `admin_legal_publish()` admin doors (later
   version only, both texts, advisory lock per document, audit).
2. **Replace, don't deprecate:** `playerDocuments()` / `organizerDocuments()` take the versions in force as an argument; the API
   reads `legal_in_force()` (sign-in request, `/v1/me`, acceptance, submission, organizer sign-up) and the settings service adds
   the `legal` block to the composed configuration (`withLegal`). The app takes the guidelines version from the configuration and
   retries once with the versions in force when the server says stale.
3. **Players:** launch gate and sign-in refusal as before (Q-095 part 1 decided: keep, Q-405).
4. **Organizers:** `organizer_legal_missing(org)` (documents accepted at an earlier version and not the one in force; only to
   a member), `accept_organizer_documents(org, docs)` (owner only). The organizer scope hook refuses writes with 403
   `organizer_acceptance_required` while documents wait; GET, leaving, an owner removing a member and the acceptance stay open;
   support is exempt. `/v1/staff/me` memberships carry `legalPending`; the dashboard shows a banner with links and the owner's
   Accept button. An organizer with no acceptance on record is not held (it can only exist in test fixtures).
5. **Help:** `help_article` (language complete or empty), console tab, `GET /v1/help`, web `/{lang}/help`, the app's Get help screen.
6. **Console:** one page `/console/legal` with two tabs (documents, help), the catalog's cards, revert for help, a confirmation
   before a publish.
