## Data (migration 0031)

1. **`flag`** `(id uuid, organizer_id, event_id, enrollment_id, kind 'shared_device'|'burst', device_id uuid NULL
   (shared_device only, CHECK), evidence jsonb, status 'open'|'cleared'|'confirmed', resolution NULL|'cleared'|
   'points_removed'|'banned' (set iff status <> 'open'), note text NULL (1–300), raised_at, last_seen_at, resolved_at,
   resolved_by uuid REFERENCES staff_user ON DELETE SET NULL)`; FKs to enrollment and event like `quest_completion`.
   - `UNIQUE (enrollment_id, device_id) WHERE kind = 'shared_device'`: one case per account and phone, ever (a cleared
     "siblings share a phone" case does not come back on the next scan; a new account on that phone gets its own).
   - `UNIQUE (enrollment_id) WHERE kind = 'burst' AND status = 'open'`: one open burst case; more bursts add to it.
   - Forced RLS, **no grants** to the API role (read and write through definers only); revoked from PUBLIC.
   - Index `(event_id, status, raised_at DESC)`; `quest_completion` gains indexes `(event_id, device_id) WHERE
     device_id IS NOT NULL` and `(enrollment_id, created_at)`.
   - Personal data: `device_id` (the install id) and `evidence` go with the account (T-217 note); never in logs.
2. **`enrollment`** gains `redeem_paused_at timestamptz NULL` (FR-518); not in any API grant; written only by
   `set_redeem_pause`.
3. **`event`** gains `flag_hold boolean NOT NULL DEFAULT true` (FR-1815); not in the API role's UPDATE grant; written
   only by `set_flag_hold`.
4. **`flag_tuning()`** IMMUTABLE: burst = **10 or more** counted completions within **5 minutes** (Q-074, Q-120;
   console-editable in T-703).

## Detection (ADR-153)

An `AFTER INSERT` trigger on `quest_completion` (`raise_completion_flags`, definer, no grant) covers every path
(own scan, station scan, manual) without copying `record_completion`. It runs inside the completion's transaction,
under the enrollment lock `record_completion` already holds, so a flag is visible the moment the scan commits.

- **Same device:** when the row has a `device_id`, find the other enrollments of the event with a completion from
  that device, after `pg_advisory_xact_lock(hashtextextended('device:' || event_id || ':' || device_id, 0))` (two
  accounts scanning at once on one phone serialize, so the second always sees the first; CTO). If any: insert a `shared_device` case for **every** account on that device (`ON CONFLICT DO NOTHING`),
  **in enrollment-id order** (two accounts scanning at once cannot deadlock on each other's unique keys). Both
  accounts are held at the desk: the desk cannot tell which one is the real player. Station scans carry no device id
  and never match. Evidence is read live on the page (the accounts on that device now), so an older case never
  needs a cross-account update.
- The trigger returns at once for method `manual` (a person chose that award).
- **Burst:** count the enrollment's completions with method `qr`, `code` or `my_qr` (a station scan; not `manual`: a person
  chose that) in the last 5 minutes **and after its last resolved burst case**. At 10 or more: insert the open case
  or add to it (`last_seen_at`, the completion ids, capped at 50). Only the player's own row is touched.
- A detector never raises an exception: a failure there must not refuse a scan (FR-329). It is plain SQL with no
  outside call; a bug surfaces in tests, not as swallowed errors (no `EXCEPTION WHEN OTHERS`).

## The desk (ADR-154)

One helper `desk_hold(enrollment, event) RETURNS text` (`NULL`, `'paused'`, `'held'`), called in
`finish_handover` under its enrollment lock (both confirm paths), in `desk_hand_over`'s offer branch (no offer to a
held player), and in `desk_lookup` (a new `hold` column, the same on every row). Order:
1. `redeem_paused_at IS NOT NULL` → **paused** (FR-1604).
2. `status = 'banned'` → **held** (FR-1747; today it is the generic RA403).
3. `event.flag_hold` and an open flag → **held** (FR-1815).

Refusal: `RH409`, DETAIL `paused` or `held`. Left and removed players keep RA403. **The hold check runs before the
`enrolled.status <> 'active'` check** in `finish_handover` and the offer branch, so a banned player gets RH409 `held`,
never RA403 `banned` (CTO MAJOR).

- **The desk never reveals a ban:** `desk_items` returns no enrollment status, only `hold` (and `active false` for a
  player who left or was removed, read as "not in this event"). The API's and the app's `banned` branches go. A test
  checks that no desk answer (lookup, find, hand-over, accept, cancel) contains `banned`.

- The operator sees **"Held, ask the owner"** for a flag or a ban, never which (the operator only needs to wait);
  paused shows OPERATOR_MODE's paused screen. Cancel stays available (it only returns points).
- **The ban's "release" is lifting the ban** (FR-1747 amended): no per-item release. Lifting it makes the items
  handable again; the owner can also cancel them.
- **The player:** a flag or ban hold tells the player nothing new (Collect still works; the desk explains). A pause
  refuses `reserve_reward` and `start_collect` with `RP403` and the app says "Redeeming is paused for you in this
  event. Ask the event team." (FR-518). `accept_handover` gets it through `finish_handover`.
- The pause check sits after the replay check in `reserve_reward` (a replay of an earlier reservation still answers
  it), next to RA403; the same place in `start_collect`.
- A held row shows the pickup time left. A held reservation keeps its pickup timeout (Q-120): the owner has the pickup time (default 120 minutes) to act;
  if it runs out, the points come back as for any reservation.
- **Find by username or phone (FR-1848, ADR-156):** `desk_find(event, by_username, by_phone)` for an operator with
  `hand_over` (not `award`): exact username (folded) or exact Saudi mobile, normalised to E.164 with the shared
  validator, among the event's members **except removed ones**; finding yourself is refused (OY409); the request body
  is kept out of logs (redaction checked by a test). The same columns as `desk_lookup` (its body moves to one internal
  `desk_items(...)` both call). Safe without My QR because every
  handover still needs the player's Collect or Accept in their own app (ADR-137). Rate limit 30 per operator per 10
  minutes (the award find's limit).

## Owner and team actions (ADR-155)

| Action | Who | Function | Audit |
|---|---|---|---|
| Read flags | owner, editors in scope | `event_flags(event, status, before, page)`, `flag_detail(event, flag)` | — |
| Clear a case | owner, editor | `resolve_flag(event, flag, 'cleared', note, request)` | `event.flag_cleared` |
| Close as points removed | owner, editor | `resolve_flag(…, 'points_removed', …)`: refused (`FN409`) unless a `removal` entry for that enrollment was written after `raised_at` (the removal itself is T-207's `remove_award`, from the case) | `event.flag_confirmed` |
| Ban | owner | `set_enrollment_ban`, replaced in 0031: a ban also closes the player's open cases (`resolution banned`, `resolved_by app_staff_user_id()`) | existing + one `event.flag_confirmed` per case, with the request id |
| Pause / resume redemption | owner | `set_redeem_pause(event, enrollment, paused, request)` | `event.redeem_paused/resumed` |
| Hold on/off | owner | `set_flag_hold(event, on, request)` | `event.flag_hold` |

`resolve_flag` locks the enrollment, then the case, so it serializes with `finish_handover`. A resolved case cannot be
reopened (`FN409 resolved`). Editors are limited to their events (`in_event_scope`). The detail shows: the player, the
kind, when, the evidence (same device: the accounts and their last scans; burst: each completion's quest, time,
method and operator), the player's held desk items, whether redemption is paused, the actions taken, and the
removal entries written since the case was raised.

## API (`docs/API.md`; new module `apps/api/src/flags`, desk additions in `src/desk`)

- `GET …/events/{eventId}/flags?status=open|closed&before=` → `{flags: [...], next}`; `GET …/flags/{flagId}`.
- `POST …/events/{eventId}/flags/{flagId}/resolve` `{resolution: cleared|points_removed, note?}` → 409 `resolved`,
  409 `no_removal`.
- `PUT …/events/{eventId}/players/{enrollmentId}/redeem-pause` `{paused}` (owner; 403 `not_owner`).
- `PUT …/events/{eventId}/flag-hold` `{on}` (owner); the value joins the event read.
- `POST /v1/operator/events/{eventId}/desk/find` `{username}|{phone}` → the lookup's answer or `{player: null}`;
  429 `too_many_attempts`.
- The desk lookup gains `hold: null|"held"|"paused"`; hand-over and accept answer 409 `held` / `paused`; reserve and
  collect answer 403 `redeem_paused`.
