# T-608 - Exports, sponsor totals and the one-page report (plan note)

Tier B: reads of existing rows and one audit write; no point is written, nothing about sign-in, the points record or tenant isolation
changes (every door sits behind `award_event_of`, as the analytics of 0102). Delivers FR-1206 to FR-1208, FR-1306, FR-1626 (and the
survey results in the report, FR-1624). Migration **0103** (staging runs through 0101). Proposed ADR-393, Q-360.

## What is built

- Doors (read-only, no table, no index): `export_start` (seat, audit `event.export`, event names, join fields), `export_players`,
  `export_completions` (paged), `export_redemptions`, `export_submissions`, `export_surveys`, `analytics_sponsor`.
- API (`apps/api/src/analytics`): `POST …/exports/{kind}` writes the CSV in pieces from the rows, each checked against a strict schema;
  `GET …/analytics/sponsors/{id}` and the sponsor file apply the floor of 5 (`MIN_GROUP_SIZE`); `POST …/report` composes the report.
- Shared (`packages/shared/src/exports`, `analytics/sponsor.ts`): schemas, the file tables, the floor (`groupCount`, `groupParts`),
  `buildReport`. `csvLines` joins `csvFile` in `text/csv.ts`; the survey spreadsheet gains `surveyResultsLines`.
- Dashboard: the Analytics page gets a sponsor filter (totals instead of the event's figures), an Export section (five files, or the
  sponsor's totals file) and a One-page report button; `/analytics/report` is the sheet and its print style (A4, one page).
