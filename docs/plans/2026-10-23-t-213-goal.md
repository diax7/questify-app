# T-213 — The goal on Home: a pinned reward, or the next reachable one

Delivers FR-517, FR-803, FR-422, FR-1616. Standard bar (not core: no ledger, stock or handover change), so no plan
review; one Sonnet code review. Migration **0033**. Depends on T-201 (`shop_rewards`, 0024/0029) and T-113 (Home).

Dhia is away: the scope choice is my recommendation, written as **Proposed** ADR-161 and Q-126.

## Scope (ADR-161)

- **In:** the player pins one reward per event as their goal (FR-517); Home shows the goal and what is left to earn,
  or the next reward they can reach when nothing is pinned (FR-803, FR-422, FR-1616).
- **Already built:** shop sections and tags (FR-516, T-201): the task line's "shop sections" needs nothing more.
- **Moved to T-304 (Proposed):** FR-522, an item as a quest's or category's reward. It needs category completion
  (T-304) and a non-shop handover; T-201 already sent its partner FR-1617 (out of stock → points only) there.

## Rules

- **Pinned goal:** the pinned reward while it is in the shop (not removed), not closed and under the player's limit,
  whatever its stock; `left` = price − balance, never below 0 (0 means "you have enough"); `soldOut` when no stock is left. A removed,
  closed or at-limit reward's pin is ignored (Home falls back to the next reachable reward).
- **Next reachable (FR-1616):** with no usable pin, the cheapest reward the player cannot yet afford (price > balance)
  that is in stock, not past its closing time and not at the player's limit; the first in shop order on a tie. A
  reward not yet open still counts (it is reachable later). None → no goal line (every reward affordable, or none).
- The goal follows the shop switch: with the `shop` feature off, Home shows no goal.
- Pinning is allowed to any active member at any status (it changes nothing but the view); a rehearsal account's pin
  goes with its enrollment at the wipe.

## Data (migration 0033)

- `enrollment.goal_reward_id uuid NULL`, FK `(goal_reward_id, event_id) → reward (id, event_id) ON DELETE SET NULL
  (goal_reward_id)`, partial index. Not in any API write grant.
- `set_goal(event, reward | NULL)` (definer): the caller's active enrollment in an active player; the reward must be
  active in that event; RN404 for a stranger, an unknown or removed reward, or another event's reward (one answer).
  Revoked from PUBLIC, granted to the API role.

## API

- `PUT /v1/events/{eventId}/goal` `{ rewardId: uuid | null }` → `{ goalRewardId }`; 404 `not_found` otherwise. A PUT
  is idempotent by nature: no key.
- `GET /v1/events/{id}/shop` gains `goalRewardId`. `GET /v1/events/{id}/home` gains `goal`
  `{ rewardId, name, price, left, pinned, soldOut } | null` (from `shop_rewards`, picked by `pickGoal`).

## App

- Rewards tab: each card has "Pin as goal" / "Unpin"; the pinned card says "Your goal".
- Home: the goal card under the standing: "Your goal" or "Next reward", the name, "{count} more {currency} to go"
  (hidden once the event ended), "You have enough {currency}.", or "Sold out"; tapping opens Rewards. An older API with no `goal` shows no card.

## Tests

- DB: `set_goal` pins, clears, refuses a stranger, a removed reward and another event's reward; deleting a reward
  clears the pin. Outsider: no grant on `set_goal` for anon. Cross-tenant: a player of event B cannot pin A's reward.
- Unit: `pickGoal` (pinned, pinned and removed, cheapest, ties, sold out, closed, limit, all affordable).
- Routes: PUT goal (200, null, 404, 400), Home's `goal`, shop's `goalRewardId`, shop feature off.
- App: `readHome` with and without `goal`; `goalLine`; `setGoal` answers.
