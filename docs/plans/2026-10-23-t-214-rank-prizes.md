## Data (migration 0034)

1. **`rank_prize`** `(id, organizer_id, event_id, rank_from, rank_to (1–100, from ≤ to), kind 'item'|'experience',
   name_ar, name_en (one required), description_ar, description_en, status 'active'|'removed', created_at,
   updated_at)`. Organizers create and edit under RLS with column grants, as `reward` (T-201). A guard trigger:
   - ranges of active prizes never overlap, checked under `pg_advisory_xact_lock(hashtextextended('rank_prize:' ||
     event_id, 0))` (the T-209 device-lock scheme), so two inserts cannot both pass;
   - an item needs the desk's place (as `reward_desk_guard`);
   - **ranges, kind, adding and removing are locked once the event is live** (`RF409 prizes_locked`, like
     `event_spend_rank_guard`, 0025); names and descriptions stay editable until confirmation;
   - every write is refused once the event's results are confirmed (`RF409 results_final`).
   - Audit: `event.rank_prize_created/updated/removed` (AFTER trigger, with the staff user).
2. **`event`** gains `rank_prizes boolean NOT NULL DEFAULT true` (FR-519's switch) and `rules_ar`, `rules_en` (plain
   text, 1–10,000). Granted to the organizer's UPDATE; the switch locks once live (same rule). Audit
   `event.rank_prizes_switched`, `event.rules_updated`.
3. **`event_result`** `(event_id PK, organizer_id, confirmed_at, confirmed_by staff_user, revealed_at NULL,
   revealed_by NULL)`. A row = the results are frozen. No API grant; definers only.
4. **`result_place`** `(event_id, rank, enrollment_id, score, score_version, open_flags int, rank_prize_id NULL,
   redemption_id NULL, PK (event_id, rank))`: the frozen top places, `max(10, highest prize rank)` rows. No API grant.
5. **`redemption`** gains `rank_prize_id uuid NULL` (FK with event, RESTRICT); `reward_id` becomes NULL-able with
   CHECK exactly one of the two; `price` CHECK becomes `price >= 1` for a reward and `price = 0` for a rank prize;
   partial `UNIQUE (rank_prize_id, enrollment_id) WHERE rank_prize_id IS NOT NULL`. A rank prize is never in a shop
   read: every shop path joins `reward`, so it fails closed (ADR-162).
6. **Every `reward_id` reader** is changed to read `rank_prize` when `reward_id` is NULL (or confirmed to skip it on
   purpose), each with a test using a rank-prize row: `desk_items` (lookup and `desk_find`), `operator_desk`,
   `desk_redemption`, `operator_cancel_redemption`, `my_desk_items`, `my_redemptions`, `start_collect`,
   `accept_handover`, `finish_handover`, `end_reservation`, `cancel_redemption` (its stock join), `flag_detail`
   (0031: an inner join on `reward` that would hide the held prize), `member_activity` (0023/0024),
   `wipe_rehearsal`, and the API's `apps/api/src/rewards/shop.ts` redemption mapping (`rewardId`, name, price).
   The implementer re-greps `reward_id` and `JOIN reward` across migrations and `apps/api/src` before phase 1 ends.

## Rules

- **Winners (FR-520):** `ranked_enrollments(event)` rows with `ranked`, ordered by score, then the lower
  `score_version` (who got there first): the same order as the board, from PostgreSQL, never Redis. Team, operators,
  banned players and the exclusion list are already out.
- **Preview** `results_preview(event)` (owner and editors in scope): state `not_ended | open | confirmed | revealed`;
  the top places with username, avatar, score, the prize for that rank, and the open-flag count and kinds
  (`flag` rows `open` for that enrollment). Once confirmed, it reads `result_place` instead.
- **Confirm** `confirm_results(event, expected uuid[], request)` (**owner only**; ADR-163):
  - only when the event has **ended** (`event_status_now = 'ended'`); refused while draft, live or archived (`RF409`
    `not_ended`). By then manual awards are already closed (they need `live`), so the score is final but for
    removals and ADR-135's cancel return.
  - locks the event row, recomputes the places, and refuses (`RF409 results_changed`, nothing written) unless they
    equal `expected`, the enrollment ids in order the owner saw. Open flags never block: they are shown and the
    confirmation dialog names them ("or ban first": a ban drops the player, the next one moves up on refresh).
  - writes `event_result` and `result_place`; audit `event.results_confirmed` with the request id. A second call
    replays.
- **The freeze:** `remove_award` (0032's version) first takes `SELECT 1 FROM event WHERE id = … FOR KEY SHARE`,
  **before** the enrollment lock, then refuses if `event_result` exists (`RF409 results_final`). `confirm_results`
  locks the event `FOR UPDATE`, so the two serialize: a removal that got the event first commits and the confirm then
  sees its score; a confirm that got it first makes the removal refuse. Same lock order everywhere (event, then
  enrollment). The T-207 note is closed by this.
- **After confirmation (ADR-163, Q-129 settled: no pass-down, no re-issue in v1):** a ban, flag or ADR-135 cancel
  return changes nothing in `result_place`. Leftovers the owner handles by hand: a banned winner's prize is held at
  the desk (`desk_hold`) and the owner may cancel it; a winner who left or was removed keeps the place, their item
  is shown as not collectable (`active false`); an unclaimed prize expires at the deadline. None of these move a
  prize to the next place.
- **Reveal** `reveal_results(event, claim_until, request)` (**owner only**; ADR-164): needs a confirmed, unrevealed
  result.
  - **Claim deadline** (ADR-162; Q-130 settled): the owner picks `claim_until`; the dashboard offers the default (the
    end of the desk's last open window when hours are set, else the shop's closing, `ends_at + shop_days_after`).
    Refused (`RF409 bad_deadline`) unless at least 1 hour and at most 60 days from now; refused (`RF409
    desk_closed_until_deadline`) when the desk has hours and none of them falls between now and `claim_until`.
  - When `rank_prizes` is on, each place with an active prize gets a `redemption` (`status reserved`, `price 0`,
    `rank_prize_id`, `reserved_until = claim_until`), and its id is stored on `result_place.redemption_id`.
    **Idempotency** comes from that column (a place that has one is skipped) and the partial unique key, never from
    the player's key space: the redemption's `idempotency_key` is `rank prize <rank>` — it contains a space, which the
    API's key format refuses, so no player request can collide with it.
  - Every replay comparison on `redemption` uses `IS DISTINCT FROM` (a NULL `reward_id` must not compare as "same"):
    `reserve_reward` (0031, and the rehearsal version, 0032:1088 `earlier.reward_id <> target`).
  - Sets `revealed_at`; audit `event.results_revealed` with the deadline. A second call replays. No ledger entry: the
    prize takes no points (FR-521).
- **The desk:** the rank prize is a reserved desk item like any other: `desk_items`, `my_desk_items`,
  `my_redemptions`, `desk_redemption`, `start_collect`, `accept_handover` and `finish_handover` read the name and kind
  from `rank_prize` when `reward_id` is NULL and return `rank` (NULL for shop items). Handover writes the existing
  `handover` entry (0, 0). The flag hold, ban hold and pause apply unchanged.
- **No price, no return:** the player cannot cancel a rank prize (`RK409`); an operator's cancel and the timeout end
  it with **no** `redeem_return` entry and no stock move (`end_reservation` skips both when `rank_prize_id` is set).
- **Rehearsal:** results need an ended event, so rehearsal never confirms; the wipe has nothing to remove.

## Official rules (store gate: STORE_COMPLIANCE §1.12, Apple 5.3.1/5.3.2, Google §2.9; ADR-165)

- The API builds a **fixed rules block** from data (`packages/shared`, Arabic and English, Western digits), never
  typed by the organizer:
  1. Questify administers the contest; the organizer provides the prizes (wording marked for counsel, Q-040/Q-041);
  2. Apple and Google are not sponsors and are not involved in any way;
  3. how winners are picked: the final score at the end, ties go to whoever reached that score first, the
     organizer's team, operators, banned players and the exclusion list cannot win;
  4. the number of winners and each rank's prize, from active `rank_prize` rows;
  5. the end time (event's zone) and the claim rule ("collect at the prize desk before the deadline the organizer
     announces with the winners"; after the reveal, the actual deadline).
- The organizer's `rules_ar`/`rules_en` go **below** the block, as plain text.
- Shown **natively in the app**: the info page renders the rules from the event read (no link-out only). The web page
  `/[lang]/e/[code]/rules` shows the same; it is **never empty** while active prizes exist (the block alone), 404 only
  when there are no active prizes and no organizer text.
- Visibility equals the event read: 404 for a draft or archived event (test).
- With the switch off, the block is not shown (no prizes are offered).

## API (`docs/API.md`; new module `apps/api/src/results`)

- Organizer: `GET|POST …/events/{eventId}/rank-prizes`, `PATCH|DELETE …/rank-prizes/{id}` (409 `overlap`,
  `results_final`, `desk_needed`); the event update gains `rankPrizes`, `rulesAr`, `rulesEn`.
- `GET …/events/{eventId}/results` → `{state, places: [{rank, enrollmentId, username, avatar, score, prize,
  openFlags}], confirmedAt, revealedAt, deadline}`; `POST …/results/confirm` `{expected}` (403 `not_owner`, 409
  `not_ended`, `results_changed` with the new places); `POST …/results/reveal` `{claimUntil}` (409
  `not_confirmed`, `bad_deadline`, `desk_closed_until_deadline`); the results read carries `defaultClaimUntil`.
  Rank-prize writes answer 409 `prizes_locked`.
- Player: `GET /v1/events/{eventId}/results` → `{revealed: false}` or the places with prizes plus `me: {rank, prize,
  redemptionId, deadline, status}`. Home gains `win` (the same `me`) while the prize is reserved.
- Public and player event reads gain `rules: {block, organizerText}` (both languages; the block as structured lines
  the clients render, so both use the same text).
- Desk and redemption answers gain `rank`; cancel answers 409 `rank_prize`; removal answers 409 `results_final`.

## Tests

- **Database:** winners skip team, operators, banned, excluded; ties by `score_version`; preview with open flags;
  confirm refused (live, draft, archived, editor, wrong `expected`, cross-tenant); replay; **races** (two
  connections, held transactions): two confirms (one writes); **removal vs confirm in both orders** (removal holds
  the event first → confirm waits, then sees the lower score; confirm holds it first → removal gets
  `results_final`); a ban against a confirm with stale `expected` (`results_changed`); after confirm: removal
  refused, ban and cancel return leave places unchanged, rank prize edits and the switch refused; prize ranges, kind,
  add and remove refused once live while names stay editable; audit rows for each prize, switch and rules write;
  reveal: only prize ranks get items, switch off gives none, price 0, `bad_deadline` (under 1 hour, over 60 days),
  `desk_closed_until_deadline`, replay creates nothing new; **a player who already used `rank prize 1`-style keys
  cannot (the API refuses the space) and a key written directly for the winner's enrollment does not stop the reveal**;
  `reserve_reward` replays compare with `IS DISTINCT FROM` (a rank-prize row under the same key answers `RK422`);
  desk handover of a rank prize (balance and score unchanged, the 0/0 entry), player cancel refused, operator cancel
  and expiry write no ledger entry, the flag and ban holds apply; **each `reward_id` reader listed in Data 6 with a
  rank-prize row**; overlap refused, including two inserts at once; a rank prize never appears in `shop_rewards`,
  `event_shop` or `reserve_reward`.
- **Rules:** the block's lines from data (winner count, prizes, end time, deadline after reveal), never empty with
  active prizes, hidden with the switch off; the page and the read 404 for draft and archived events.
- **Outsider and cross-tenant** (`apps/api/test/security`): the new tables unreadable; every new function refused
  for the API role without context, another organizer, and `anon`/`PUBLIC`.
- **Routes and unit:** every status above; the player read before and after the reveal.
- **Browser:** the Prizes and results page (edit, confirm with a flagged player, reveal); the rules page.
