## Safe scope and actual source exercised

- `apps/api/test/support/t503-rank-probe.sql` is explicitly NOT a migration. Only the opt-in test
  loads it into its own disposable database after all production migrations through 0081.
  0082 is free and remains free. No existing migration, application adapter or production schema changed.
- The fixture moves the original `complete_quest` function (0057's current definition) into a
  private schema and wraps its original signature with shared G then exclusive E acquisition,
  before its existing first source lock. The API role calls the public wrapper, not a fake payer.
  The original body calls current `record_completion` (0062), the actual rehearsal/open/proof/cap
  checks, quest_completion INSERT, ledger INSERT, enrollment update, XP/streak/personal-notice
  triggers, item/category/first-bonus paths and actual COMMIT. Nothing in that chain is mocked,
  disabled or replaced with a synthetic snapshot query during any measured completion.
- Initial players, contacts, enrollments and initial positive scores/versions are bulk fixture data,
  NOT 50,000 earned ledger histories. Setup triggers are enabled. The fixture contains no team members,
  exclusions, devices or rehearsals. This is the easier active/eligible hot-event case, not the
  worst-excluded-leaders case or a full business-history soak test.
- Each source update maintains only its changed eligible projection entry. A covering ordered index
  supplies the top ten; a deferred dirty-row trigger finalizes once/event/transaction, writing
  the new snapshot, monotonic revision, crossing facts and exact latest identity atomically.
  No normal completion rebuilds/scans attendees in the NEW projection code. Existing source SQL
  was not profiled sufficiently to assert that its entire chain contains no attendee scans.
- The private relation is the probe's DB publication boundary. Production Redis overall reads,
  afterCompletion, fallback, repairs and today-cache are deliberately UNCHANGED. The coherent
  overall API cutover is NOT implemented or claimed; failure prevents activating this candidate.

## Source inventory status and technical redesign recommendation

This is a partial inspected inventory, NOT an exhaustive writer certificate. Current definitions
include `complete_quest` 0057, `record_completion`/`pay_submission`/`wipe_rehearsal` 0062,
`reserve_reward` 0074 and `erase_rows` 0076. In particular, the historical plan table's
"wipe_rehearsal latest 0055" is not current. `ensure_rehearsal_wiped` (0032) can enter a
go-live wipe from an otherwise ordinary payer: classify/reset BEFORE entry, never upgrade G
under shared G/E/legacy locks. `kiosk_complete_quest` (0058:334) takes device FOR SHARE before
calling the payer; acquiring G only inside `record_completion` is too late. No such incomplete
central-hook fix has been installed. NFC/operator/meet/bulk/refund/item/category doors and cascades
still require complete transitive inspection and both-order proofs.

Raw writer checkpoints inspected: `organizers/team.ts:295,350` (scope/delete),
`settings/store.ts:37,50,76,102,123,145` (platform defaults/event overrides/entitlements),
`events/store.ts:209,252,290` (event insert/update/delete). These need OUTERMOST G before
existing row locks, inherited-settings affected-event discovery, sorted E and actual source reset
edges. The fixture intentionally does NOT pretend its enrollment-only guard covers these doors.

**Stop for coordinator technical redesign (Proposed ADR-361 / Q-330).** Profile and reduce the
actual full source cost first; do not optimize only the top query and call this passing. Alternatively
evaluate a terminal, short event-publication fence AFTER business work, with all source/legacy
lock acquisition finished before that fence and a proven no-back-edge lock graph. That is a NEW
protocol needing explicit coordinator acceptance and exhaustive READ COMMITTED visibility,
rollback, lifecycle/global guard, FK/cascade and both-order proofs; NOT a worker-approved change
to ADR-359. Preserve ordered committed crossings, exact identity/generation, canonical eligibility,
coherent top/own/total and FR-613. Do not coalesce, omit visible transitions or relax 20k/minute.

No email/UI/provider/auth-failover change, operational send, T-504, subagent, push, deploy, EAS,
local mutation, task tick or self-approval. Mail remains default OFF, retries remain an empty
allowlist; T-609 reuses the eventual infrastructure and missing T-701 sources remain future.
